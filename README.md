# ruoyingking 使用说明

```
ruoyingking/
├── index.html   网站本身
├── admin.html   内容编辑器 —— 平时都在这里写东西
├── data.js      公开内容（会随网站发布）
├── private.js   私密台账（只留在本地，不要上传）
├── fonts/       标题字体（子集，160 KB）
├── totem.json   龙纹图腾的线稿数据
├── totem.js     上面那份的内嵌副本
├── photos/      照片文件夹
├── robots.txt   告诉搜索引擎不要收录
└── README.md    这份说明
```

## 口令

| | 口令 | 作用 |
|---|---|---|
| 访问 | `1126` | 打开网站时输入，才能看到内容 |
| 编辑 | `20051126` | 点右上角「✎ 编辑」后输入，进入编辑器 |

输入过一次会记住，同一台设备下次不用再输。想重新上锁，点网站底部的「锁定」。

**改口令**：打开 index.html，搜索 `GATE_PASS`，那两行就是。改完把 admin.html 里的 `EDIT_PASS` 改成一样的值（两处必须一致）。

### 这道口令能挡住谁

**能挡住**：随手点进来的人、搜到网址的陌生人、把链接转给别人的同学。

**挡不住懂技术的人。** 原因是网页的口令是在访客自己的浏览器里判断的，而你的内容存在 `data.js` 这个独立文件里。任何人在地址栏直接输：

- `你的网址/data.js` → 能读到全部文字，包括随笔正文
- `你的网址/photos/照片名.jpg` → 能看到照片原图

这两条路径不经过口令页面。另外，GitHub Pages 免费版要求仓库是 public，所以在 GitHub 仓库页面上，同样能下载到这些文件。

所以请把它理解成**门牌**，不是锁。

### 如果需要真正的保护

前提是内容里有访谈对象的照片、涉及机构的敏感反思这类不能外泄的东西。免费且有效的做法是 **Cloudflare Pages + Cloudflare Access**：

1. 仓库设为 private（Cloudflare Pages 免费版支持私有仓库，GitHub Pages 不支持）
2. 在 Cloudflare Pages 部署这个仓库
3. 开启 Zero Trust → Access，设成"只有指定邮箱能访问"

之后所有人（包括访问 data.js 和照片）都要先通过邮箱验证码，免费版够 50 个人用。设置比 GitHub Pages 麻烦一些，但这是真的锁。

**关于口令本身**：`20051126` 看起来像生日。网站上会写你的名字，认识你的人不难猜到。如果哪天你打算把访问口令给别人、只留编辑口令自己用，建议把编辑口令换成一个跟你无关的字符串。

## 栏目（档案袋）随时可改

打开编辑器 → 左侧「栏目」，在这里可以：

- **改名字和说明** —— 直接在输入框里改
- **换颜色** —— 点一个色块就行，袋身的深浅和字色会自动配好，不用挑四个颜色
- **调顺序** —— 用 ↑ ↓，顺序就是桌面上袋子的排列顺序
- **删除** —— 点「删除」，会先确认
- **新增** —— 点最下面的「+ 新增一个栏目」，填名字、选类型

新增栏目时要选一个**类型**，决定它怎么展示：

| 类型 | 长什么样 | 例子 |
|---|---|---|
| 文字 | 一整篇文章 | 关于 |
| 条目 | 卡片列表，每条有标题、简介、标签 | 作品 |
| 文章 | 列表点进去读全文 | 随笔 |
| 照片 | 分组相册 | 回忆 |
| 时间轴 | 分阶段的目标，带状态标记 | 规划 |

新栏目建好后，左侧会立刻多出一项，点进去就能填内容。桌面上的袋子、右侧色块、条目计数全部自动跟上，不用改任何代码。

**两点说明**：

栏目的「网址标识（id）」是锁定的，因为内容是按 id 存的，改了会和内容失去关联。想换名字改「名字」那一栏就行，id 不影响显示。

类型定了不能改。想把一个「条目」栏目变成「文章」，新建一个再把内容搬过去。

**删除栏目后内容还在** —— 它只是不再显示。如果你之后用同一个 id 重新建一个同类型的栏目，内容会自己回来。真想彻底清掉，手动编辑 data.js 里 `store` 下对应的那一项。

## 这一版做了什么优化

**字体**：标题改用 Noto Serif CJK 的子集（`fonts/rk-serif.woff2`，160 KB，只含网站用到的约 650 个字）。以前用系统宋体，在 Windows 上会退成 SimSun，大字号下笔画很糙——你自己电脑上看到的效果和别人看到的不一样。现在统一了。字体是 SIL 开源许可，可以随网站发布。

**颜色**：六个栏目的色相重新拉开（卡其 / 梅子 / 深红 / 松石 / 石青 / 苔绿），全部降了饱和度，并且都避开荧光黄绿。**荧光色现在只有一个含义：当前、正在进行。** 路线图上的「我在这里」、主线那句话的左边线，只有这些地方用它。颜色一旦有了含义，就不再只是装饰。

**间距刻度**：全站统一用 8 / 16 / 24 / 40 / 64 五档，标题三级，正文宽度统一 36em。以前各页节奏略有出入，读者说不出哪里不对，但会觉得不精致。

**栏目条**：进入任何栏目，顶部都有一条横向导航，可以直接跳到别的栏目，不用退回桌面。当前栏目用它自己的颜色高亮。

**空状态**：每种类型有自己的话。相册空着时写的是「等有舍不得忘的时刻再放」，不是干巴巴的「暂无内容」。

**桌面主线**：名字下面多了一句你的立场（`data.js` 里的 `thesis` 字段）。个人网站最该一眼看到的不是学历，是这个人在追什么问题。

**最近三条**：桌面左下显示最近更新，跨栏目按日期排。这是给访客看的活跃度证明，所以**私密台账和路线图的未来节点不计入**——那些不是"更新"。

**全站搜索**：桌面右上角的按钮，或者任何时候按 `/` 键。搜标题、正文、标签，↑↓ 选，回车打开。

**标签打通**：随笔和台账用同一套标签。点任何一个标签，会跳到标签页，把两边所有相关内容列在一起——这是让人能"顺着主题逛"的关键，也最能体现你思考的连贯性。所以同一个概念尽量用同样的写法。

**写作分工**（编辑器里也有提示）：

- **台账**记「发生了什么」——当场看到的，不用有结论，三十秒一条
- **随笔**写「我想明白了什么」——从若干条观察里长出来的判断

这条规矩是让台账真正发挥作用的前提。否则你每次都会犹豫该写哪儿，最后两边都不写。

## 台账（个人研究记录）

台账是第六种栏目类型，适合**一条一笔、不断累积**的记录：社会观察、读书笔记、案例收集、申请信息比对。跟「文章」不同——文章是给人读的，台账是给自己查的：顶部有搜索框，下面有标签筛选，一条一行，点开才展开全文。

现在有两本：

| 台账 | 在哪 | 谁能看 |
|---|---|---|
| 观察 | data.js | 公开 |
| 港校 | private.js | 只有你 |

### 字段自己定

每本台账有哪几栏，在编辑器的「栏目」里改：展开台账栏目 → 「字段」 → 加、删、改名、调顺序。字段有三种：

- **单行文字** —— 短的，第一个单行字段会当作这条记录的标题
- **长文** —— 支持排版标记，有实时预览
- **标签** —— 逗号隔开，会自动汇总成筛选按钮

删字段会连着已填的内容一起消失，改名字则不影响内容。

### 关于「观察」这本的写法

默认字段是：场景 / 看到什么 / 我怎么想 / 标签。

**「看到什么」和「我怎么想」分开写**，这是田野笔记的基本纪律。混在一起写，半年后你分不清哪些是当时真的观察到的、哪些是事后脑补的。分开写，日后能重新解释同一个事实，甚至推翻当初的判断——这才是记录能沉淀成研究的原因。

想法那一栏**允许空着**。强行给每条观察凑一个解释，是最伤记录质量的习惯。

### 私密台账怎么保证不外泄

私密内容存在 `private.js`，这个文件：

- **不会**被写进 data.js
- **不会**被「发布到 GitHub」上传
- 导出时要单独点「下载 private.js」

网站在本地打开时会自动读它；线上没有这个文件，那个栏目就完全不存在——直接输网址也打不开，页面源码里搜不到任何痕迹。

**你唯一要做的是：永远不要把 private.js 传到网上。** 上传文件时看清楚文件名。

想新建一本私密台账，目前需要手动改 private.js（把栏目定义和内容照着现有格式加进去）。编辑器里新建的台账默认都是公开的。

## 门厅（封面和桌面之间那一层）

顺序是：**封面（口令）→ 门厅 → 桌面（档案袋）→ 栏目内容**。

门厅上有四样东西：

- **主线句**，大字排版，就是 `data.js` 里的 `thesis`
- **总账**：开账日期、各栏目累计条数、最近一次更新是几天前——全部自动算，不用维护
- **最近三条**，可以直接点进去读，等于跳过桌面的快捷入口
- **进档案室 →** 按钮（也可以直接按回车或 Esc）

门厅的主体是**阴阳龙纹图腾**，线稿是从你上传的 FBX 模型里提取的：解析二进制 FBX → 取 20563 个顶点和 12059 个面 → 计算折痕边和轮廓边 → 投影成正面视图 → 抽稀成 2557 条折线，存进 `totem.json`（185 KB）。之前的 3D 蛇、骨骼链、游动算法、Three.js 全部移除了。

**三个图层**：

1. **背景**：暗红 `#1F080A`，带一层针织／皮革的颗粒质感
2. **浮雕层**：暗红石刻的图腾——投影、受光边、主体三道描边叠出立体感，看得见但不抢眼
3. **高亮层**：同一套线条，霓虹红加 `shadowBlur` 发光，用离屏遮罩裁出被笔刷扫过的部分

**性能**：浮雕层和发光层都是**预渲染**的（只在窗口尺寸变化时重画一次），每帧只做三次贴图合成。之前每帧要把 2557 条折线画三遍、其中两遍带 `shadowBlur`，那是 Canvas 里最贵的操作，卡顿就是这么来的。现在容器里软件渲染实测 39 fps，真实设备上会更高。

**交互**：

- **划过即亮**：鼠标像一束光笔刷，半径 70px（快速移动时扩到 108px），扫到哪里哪里从石刻转成发光
- **余辉**：1.5 秒指数级淡出，留下荧光余痕
- **移速响应**：越快光斑越宽，并散落红色粒子；停下来光斑收拢
- **鱼眼激活**：靠近太极的两个鱼眼（50px 内）触发脉冲爆闪，同时激起一圈能量涟漪扫过整条龙——涟漪扫到的线条会依次亮起

两个鱼眼的位置是自动从线稿里识别出来的（找接近正圆的闭合小环）。

**调参**：`vendor/totem.js` 顶部的 `CFG`：

| 参数 | 作用 |
|---|---|
| `bg` / `dark` / `darkAlpha` | 背景色 / 石刻线色 / 石刻可见度 |
| `glow` | 激活后的霓虹色 |
| `brush` / `brushFast` | 笔刷半径 / 快速移动时的半径 |
| `fade` | 余辉时长（秒） |
| `eyeDist` | 鱼眼触发距离 |
| `particles` | 粒子池上限 |

这一版是纯 Canvas 2D，不需要打包，改完直接生效。Three.js 已经整个移除，包体积因此小了 488 KB。

**为什么有 `totem.js`**：它是 `totem.json` 的内嵌副本。直接双击打开 index.html 时浏览器不允许读取本地 json，这时用内嵌那份；放到网上后优先读 `totem.json`。

**两个入口回门厅**：桌面右上角的「◇ 门厅」，以及每一页页脚的「门厅」。

## 界面结构

**封面页** —— 整屏的血红背景（浏览器实时画的发光脉络，会缓慢游动），左下角是名字和口令输入框，右上角是走真实时间的时钟。输入访问口令进入。

想把背景换成视频：文件命名 `cover.mp4` 放进 `photos/`，会自动铺满并盖住画的背景，删掉就退回来。建议 10 MB 以内、5–15 秒可循环。素材要用自己拍的，或 Pexels、Pixabay 这类可免费商用的；**不要用带别人账号水印的**。

**桌面** —— 进去后是一整屏黑色的 3D 轮播：五个档案袋竖向排列，缓慢地一张张转到中间，在正中停一下，再翻转着退出画面。一个颜色对应一个栏目：

| 栏目 | 颜色 |
|---|---|
| 关于 | 牛皮黄 |
| 作品 | 灰玫瑰 |
| 随笔 | 血红 |
| 回忆 | 松石绿 |
| 规划 | 荧光黄绿 |

袋子上会自动显示条目数，你在编辑器里增删内容，数字跟着变。栏目的数量、名字、颜色、顺序都能在编辑器里改（见上一节）。袋子有真实厚度（五层薄片叠出断面），正面是袋口和露出的纸，转过去的背面是压暗的磁条样式。

**怎么操作**：

- **右侧五个色块**是快捷入口，点一下对应的袋子会平滑转到中间，不用等。悬停时显示栏目名，当前在中间的那个色块会变亮变长。
- 滚轮上下拨动可以手动快进。
- 点中间那张打开栏目；点旁边那张会先把它转到中间。
- 鼠标移动时中间那张会跟着倾斜，带惯性阻尼，慢半拍。

**想调节奏**：在 index.html 搜 `var SPEED`。`SPEED` 是自动推进速度（越小越慢，默认 0.0016，约十秒一张）；`TILT_Y`/`TILT_X` 是鼠标倾斜幅度；`DAMP` 是跟随速度；`GAP` 是卡片间距；`D` 是透视距离。中心停顿的强度在 `Math.pow(Math.abs(diff)*2, 4.2)` 那一行，指数越大停得越久。

**想换栏目颜色**：不用改代码，在编辑器的「栏目」里点色块即可。

**想调封面背景脉络**：搜 `封面背景`，`var N = 13` 是丝线条数，`t += 0.016` 是速度。

## 日常怎么用

打开 **admin.html**，左边六个板块，填表格就行。改完点右上角，两条路二选一：

| | 导出 data.js | 发布到 GitHub |
|---|---|---|
| 需要配置吗 | 不需要 | 填一次令牌，之后一直有效 |
| 怎么生效 | 下载文件手动替换 | 点一下，网站一两分钟后自动更新 |
| 照片 | 要手动放进 photos/ | 自动上传 |
| 适合 | 还没上线时 | 上线之后 |

编辑器有自动草稿：中途关掉浏览器，下次打开会问要不要接着改。但**草稿只存在这台设备上，不等于发布**——顶部显示「有改动还没发布」就说明网站上还是旧的。

## 各板块的注意事项

### 随笔

点「+ 写一篇新的」，标题、日期、id 会自动填好。正文下方有实时预览，边写边能看到效果。可用的标记：

| 写法 | 效果 |
|---|---|
| `**文字**` | 加粗 |
| `*文字*` | 斜体 |
| `## 文字` | 小标题（单独一行） |
| `> 文字` | 引用块（单独一行） |
| `- 文字` | 项目符号 |

空一行 = 分段。

**id 就是文章的网址**（`#/notes/你的id`）。已经分享给别人的文章别再改 id，改了旧链接会打不开。

### 回忆

点「+ 选择照片」，可以一次选多张。浏览器会自动把图压到长边 1600px、质量 82%，一般从五六 MB 降到两三百 KB，不用你自己处理。

用 GitHub 发布的话，照片会一起传上去，什么都不用管。用导出模式的话，导出窗口里有个「下载这 N 张照片」按钮，下载后放进 `photos/`，**文件名不要改**。

点已有的照片可以改说明，点右上角 ✕ 移除。

### 路线图

「路线」是第七种类型：一张**分叉的人生地图**。走过的路在上面，当前位置发着光，前面的岔口往下分开。

每个节点有四样东西：**这一站叫什么、时间、状态、当时怎么想的**。状态有五种：

| 状态 | 显示 |
|---|---|
| 走过 | 暗色，实线 |
| 我在这里 | 荧光高亮，带辉光 |
| 在考虑 | 该栏目主色，实线 |
| 以后 | 半透明，虚线 |
| 放弃了 | 更淡，虚线，标题带删除线 |

**线路怎么接**：每个节点选一个「上一站」，选完就自动连上。一个节点底下挂了两个以上的下一站，那里就自动成为岔路口——不用手动画线。想从某一站分出新的一条，展开它点「+ 从这里分出一条」。

**点节点会展开当时的想法**，同时从起点到它的整条路径会高亮、其余变暗——能看清"如果走这条，路是怎么走的"。

**放弃的岔路建议留着，别删。** 把状态改成「放弃了」，它会变淡并划掉，但仍然在图上。这是这张地图最有价值的地方：过两年回头看，你能看见自己曾经认真考虑过什么、为什么否掉了。在「当时怎么想的」里写下否掉的理由，比结论本身有用得多。

袋子上显示的是当前有几个岔口（状态为「在考虑」的节点数）。

### 排序

所有列表都用条目右上角的 ↑ ↓ 调顺序，排在最上面的显示在最前。

## 配置 GitHub 一键发布

先把网站传上 GitHub Pages（见下一节），然后：

1. GitHub → 右上角头像 → **Settings**
2. 左侧最底下 **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. 三个关键项：
   - **Expiration**：选 90 天或自定义（到期后重新生成一个填进去就行）
   - **Repository access**：选 *Only select repositories*，**只勾你的网站仓库**
   - **Permissions** → Repository permissions → 找到 **Contents**，改成 **Read and write**
4. 生成后复制那串 `github_pat_...`——**它只显示这一次**
5. 回编辑器点「发布到 GitHub」，填用户名、仓库名、令牌，保存并发布

之后每次发布就只是点一下按钮。

**关于安全**：这个令牌只能读写你这一个仓库，做不了别的事。它存在你自己浏览器里，不经过任何第三方服务器。公用电脑上用完，点弹窗里的「清除令牌」。万一泄露，去 GitHub 把它 Revoke 掉再重新生成。

---

## 第一次发布上线

1. 注册 GitHub，新建仓库，名字填 `你的用户名.github.io`
2. 把文件夹里**所有文件**传进去（是文件本身，别多套一层文件夹）
3. 仓库 → Settings → Pages → Source 选 `main` → Save
4. 一两分钟后访问 `https://你的用户名.github.io`

上线后，编辑器仍然从本地打开用就行，不需要跟着发布。你也可以把 admin.html 一起传上去、在手机上写东西，但那样别人也能打开这个页面（他们改不了你的网站，只能在自己浏览器里瞎折腾）。介意的话就别传。

---

## 关于「编辑」入口

右上角那个「✎ 编辑」按钮平时是半透明的，点开要输编辑口令。直接在地址栏输 `你的网址/admin.html` 也会先问口令。

同样地，这挡的是随手点点的人。真想改你网站内容的话还需要你的 GitHub 令牌，那个才是关键——所以令牌别泄露，比口令重要得多。

不想要这个按钮，打开 index.html 搜索 `id="lock"`，把那一行删掉，你自己直接输 admin.html 网址仍能进。

## 出问题了

**照片显示成虚线框**
路径对不上。检查 `photos/` 里的文件名和 data.js 里写的是否完全一致（大小写、`.jpg` 还是 `.JPG` 都算）。

**发布失败**
看弹窗里的错误信息。最常见：令牌过期、权限没给到 Contents: Read and write、仓库名写错、分支不叫 main。

**页面空白**
多半是手改 data.js 时少了逗号或引号。按 F12 打开控制台，红字会告诉你第几行。改之前先备份，最省事。

**编辑器打不开内容**
确认 admin.html 和 data.js 在同一个文件夹里。

**输了正确口令还是进不去**
两个文件里的口令要一致：index.html 的 `EDIT_PASS` 和 admin.html 的 `EDIT_PASS`。

**想清掉记住的登录状态**
点网站底部的「锁定」，或者清除浏览器数据。
